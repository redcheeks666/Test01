# 任务：为纪录短片《天问》收集官方一手素材（v2 · 阶段一）

## 背景

我们在制作一部 16:9、纯音乐无旁白的科普短片《天问》，讲人类从古代神话到 2026 年星舰入轨的航天梦。全片分为：序章、壹 神话、贰 仰望、叁 先驱（传说—1947）、肆 竞赛（1957—2024）、伍 回来，再出发（2015—2026）、尾声。

画面分两类：

- 神话、理论类画面由另一个 AI（Claude）用代码绘制；
- 真实历史事件用官方实拍素材，由 Claude 负责剪辑、调色、加特效。

**你的工作：按下面的清单，把官方一手、最高清的原始素材下载到指定文件夹，为每个文件写清楚来源和授权，然后生成文件清单和预览，把这些小文件推到 GitHub 仓库供 Claude 审核。** 不要剪辑、调色、加水印或做任何艺术处理。

## 和 v1 的关系

- 如果你已经按 v1 下载过素材：**保留已有文件，不要重复下载**。按本文的编号表逐一核对，补齐 v1 没有的编号（表中"状态"列标为"新增"或"修改"的），并按本文的规则补全 manifest。
- v1 里"超过 380MB 就截片段、原件放 `_originals_large/`"的规则**本阶段作废**：所有原件原样保存在对应编号文件夹里，不截取、不转码。如果已经按 v1 截过片段，保留片段和原件，在 manifest 的 notes 里注明。大文件怎么传，由 Claude 看完 INVENTORY 后在阶段二决定。
- v1 的 PD-07（加加林）已移到 SU-04；v1 的 NA-02 和 NA-16 都保留，同一个文件不要在两个编号下重复保存。

## 来源优先级

1. 机构官方原始文件：NASA Image and Video Library、NASA SVS、JPL Photojournal、SpaceX 官网与官方 Flickr、国家航天局 / 中国载人航天 / 中国探月与深空探测网官网、ISRO 官网、ESA 官网、图书馆与档案馆的官方扫描（美国国会图书馆、BnF Gallica、e-rara、佛罗伦萨国家中央图书馆、大都会艺术博物馆 Open Access 等）。
2. 官方原件的忠实存档：如 Project Apollo Archive（NASA 照片高清扫描）、Wikimedia Commons 上许可明确的原始扫描件或档案照片（只取原图，不取重绘图）。Commons 上德国联邦档案馆（Bundesarchiv，CC BY-SA 3.0 DE）和俄新社档案（RIA Novosti archive，CC BY-SA 3.0）的照片可以用，照实记录许可。
3. 都没有时，在 REPORT.md 里写明"未找到"，不要用替代品凑数。

**禁止：** 网友二次剪辑、搬运频道、带水印的图库（Getty、Shutterstock、视觉中国等）、AI 生成或重绘的图、把渲染图当照片（官方示意图可以收，但 description 里必须写"示意图"）、任何带版权音乐的视频音轨。

## 各来源的使用方法

- **NASA Image and Video Library**：API `https://images-api.nasa.gov/search?q=<关键词>&media_type=image|video|audio`；每个条目的全部文件在 `https://images-assets.nasa.gov/<media_type>/<nasa_id>/collection.json`，下载文件名含 `~orig` 的原件。记录 `nasa_id`。
- **NASA SVS**（`https://svs.gsfc.nasa.gov`）：下载页面上最高分辨率的视频或帧序列，记录可视化编号。
- **JPL Photojournal**（`https://photojournal.jpl.nasa.gov`）：按 PIA 编号下载全尺寸 TIFF 或 JPG。
- **SpaceX 照片**：官方 Flickr `https://www.flickr.com/photos/spacex`，下载 Original 尺寸，记录照片页面地址。许可为 CC BY-NC 2.0，照实记录。
- **SpaceX 视频**：没有公开许可。官网直接提供下载的，正常下载。需要从 YouTube 或 X 抓取的，**先不要下载**，把视频链接和关键画面时间码写进 REPORT.md 的"待用户确认"一节，等用户决定。
- **美国国会图书馆**（`https://www.loc.gov`）：可用 JSON API（在搜索地址后加 `&fo=json`）；下载最大的 TIFF 或 JPEG，记录馆藏号（如 LC-DIG-…）和"Rights Advisory"原文。
- **大都会艺术博物馆 Open Access**：只取标注 Public Domain（CC0）的藏品图，记录藏品号。
- **中国航天官方**：国家航天局 `https://www.cnsa.gov.cn`、中国探月与深空探测网 `https://www.clep.org.cn`、中国载人航天 `https://www.cmse.gov.cn`、中国航天科技集团官网及官方账号。下载官方发布的最大尺寸原图；网站有版权声明的，把原文抄进 manifest 的 notes。
- **ISRO**（`https://www.isro.gov.in`）：下载官方发布的原图，抄录网站版权声明。
- **音效**：只用可商用的免费资源，并记录许可原文：Freesound（筛选 Creative Commons 0）、Pixabay Sound Effects、Sonniss GDC 免费音效包。优先 WAV 或 FLAC。
- **档案原声**：优先 NASA 官方音频（NASA Image and Video Library 的 audio 类型、NASA History 网站），记录条目地址。

## 文件规则

- 原件原样保存，不转码、不压缩、不放大、不裁切、不截取。
- 视频至少 1080p，有 4K 就下 4K；没有烧录字幕、台标以外的水印。直播画面若带数据叠加层，在 notes 里写明叠加层位置。
- 一两个小时的直播回放或长纪录片：照常下载原件，但必须在 manifest 的 `key_moments` 里写清楚关键画面的时间码（精确到秒）。阶段二会根据这些时间码截取。
- 图片取原始最大尺寸（TIFF 也行）。
- 用 ffprobe 填写分辨率、帧率、时长。

## manifest.csv

按 `manifest_template.csv`（仓库 `docs/manifest_template.csv`）的列，一个文件一行（同一编号的多个候选各占一行）。列说明：

- `asset_id`：编号，如 NA-09
- `candidate`：候选序号，01、02……
- `file_path`：相对 assets/ 的路径
- `shot_ids`：用在哪些镜头，照抄上表"用在"
- `description`：一句话描述画面内容
- `source_org`：发布机构
- `source_page_url`：素材详情页
- `direct_file_url`：实际下载的文件地址
- `original_id`：机构编号（nasa_id、PIA 编号、Flickr 照片 ID、馆藏号）
- `license`：许可（Public Domain / NASA media guidelines / CC BY-NC 2.0 / CC BY-SA 3.0 / CC0 / Pixabay License / 未声明）
- `license_url`：许可说明页
- `credit_line`：片尾署名写法，如"NASA/JPL-Caltech"
- `media_type`：video / image / audio
- `width`、`height`、`fps`、`duration_s`、`filesize_mb`
- `excerpt_of`、`excerpt_in`、`excerpt_out`：本阶段不截取，留空（v1 已截的片段照填）
- `key_moments`：视频里关键画面的时间码，如"00:12 点火; 00:19 离塔"。长视频必填
- `notes`：其他说明（叠加层位置、网站版权声明原文、拿不准的地方）

## 预览图

- 每个视频用 ffmpeg 生成一张 4×4 缩略图拼板，每张缩略图标上时间码，整张宽 1920 像素，JPEG，存为 `previews/<文件名>.jpg`。长视频（超过 10 分钟）改成 6×6。
- 每张图片生成长边 1280 像素的 JPEG 预览，存为 `previews/<文件名>.jpg`。
- 每个音频用 ffmpeg 的 `showwavespic` 生成一张 1280×240 的波形图，存为 `previews/<文件名>.png`。
- 每张预览图不超过 1MB。

## INVENTORY.md

一份给 Claude 评估传输方案用的文件清单，用脚本根据实际文件生成，不要手填：

1. **总览**：文件总数、总大小（GB）；按大类（SX / NA / SU / CN / IN / PD / FX / AU）分别统计文件数和大小。
2. **完整清单**：一个文件一行，列为：`file_path`、`media_type`、`width×height`、`fps`、`duration`、`codec`、`size_mb`。按大小从大到小排序。
3. **大文件分档**：分别列出超过 100MB、超过 380MB、超过 2GB 的文件，每档给出数量和合计大小。
4. 同时输出机器可读的 `inventory.csv`，列与第 2 条相同。
