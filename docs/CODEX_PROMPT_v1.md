# 任务：为纪录短片《天问》收集官方一手素材

## 背景

我们在制作一部 16:9、纯音乐无旁白的科普短片《天问》，讲人类从古代神话到 2026 年星舰入轨的航天梦。画面分两类：

- 神话、理论类画面由另一个 AI（Claude）用代码绘制；
- 真实历史事件用官方实拍素材，由 Claude 负责剪辑、调色、加特效。

**你的工作只有一件：按下面的清单，把官方一手、最高清的原始素材下载到指定文件夹，并为每个文件写清楚来源和授权。** 不要剪辑、调色、加水印或做任何艺术处理。

## 输出位置与结构

根目录：`/Users/mashazhenta/CodeXProject/Vibe知识大赏/assets/`

```
assets/
  manifest.csv          ← 素材清单（按 manifest_template.csv 的列填写）
  REPORT.md             ← 你的收集报告（见文末）
  previews/             ← 每个视频一张缩略图拼板，每张图片一张小预览
  SX/  NA/  CN/  PD/  FX/  AU/
    <素材编号>/          ← 例：NA/NA-09/
      NA-09_01_apollo11_ignition_slowmo_nasa.mp4
  _originals_large/     ← 超过 380MB 的原文件放这里（见“文件规则”）
```

文件命名：`<编号>_<候选序号两位>_<英文小写简述>_<来源缩写>.<原扩展名>`，只用 ASCII 字符，不要空格。

## 来源优先级

1. 机构官方原始文件：NASA Image and Video Library、NASA SVS、JPL Photojournal、SpaceX 官网与官方 Flickr、国家航天局 / 中国载人航天 / 中国探月与深空探测网官网、图书馆与档案馆官方扫描（BnF Gallica、e-rara、美国国会图书馆、佛罗伦萨国家中央图书馆等）。
2. 官方原件的忠实存档：如 Project Apollo Archive（NASA 照片高清扫描）、Wikimedia Commons 上标注为公有领域的原始扫描件（只取扫描原图，不取重绘图）。
3. 都没有时，在 REPORT.md 里写明“未找到”，不要用替代品凑数。

**禁止：** 网友二次剪辑、搬运频道、带水印的图库（Getty、Shutterstock、视觉中国等）、AI 生成或重绘的图、把渲染图当照片、任何带版权音乐的视频音轨。

## 各来源的使用方法

- **NASA Image and Video Library**：API `https://images-api.nasa.gov/search?q=<关键词>&media_type=image|video|audio`；每个条目的全部文件在 `https://images-assets.nasa.gov/<media_type>/<nasa_id>/collection.json`，下载文件名含 `~orig` 的原件。记录 `nasa_id`。
- **NASA SVS**（`https://svs.gsfc.nasa.gov`）：下载页面上最高分辨率的视频或帧序列，记录可视化编号。
- **JPL Photojournal**（`https://photojournal.jpl.nasa.gov`）：按 PIA 编号下载全尺寸 TIFF 或 JPG。
- **SpaceX 照片**：官方 Flickr `https://www.flickr.com/photos/spacex`，下载 Original 尺寸，记录照片页面地址。许可为 CC BY-NC 2.0，照实记录。
- **SpaceX 视频**：没有公开许可。官网直接提供下载的正常下载。需要从 YouTube 或 X 抓取的，**先不要下载**，把视频链接和关键画面时间码写进 REPORT.md 的“待用户确认”一节，等用户决定。
- **中国航天官方**：国家航天局 `https://www.cnsa.gov.cn`、中国探月与深空探测网 `https://www.clep.org.cn`、中国载人航天 `https://www.cmse.gov.cn`。下载官方发布的最大尺寸原图；如果网站有版权声明，把原文抄进 manifest 的 notes。
- **音效**：只用可商用的免费资源，并记录许可原文：Freesound（筛选 Creative Commons 0）、Pixabay Sound Effects、Sonniss GDC 免费音效包。优先 WAV 或 FLAC。

## 文件规则

- 原件原样保存，不转码、不压缩、不放大、不裁切。
- 视频至少 1080p，有 4K 就下 4K；没有烧录字幕、台标以外的水印。直播画面若带数据叠加层，在 notes 里写明叠加层位置。
- 图片取原始最大尺寸（TIFF 也行）。
- 单个文件超过 380MB：原件放进 `_originals_large/`，另外用 ffmpeg 截出包含关键画面的片段放进对应编号文件夹（前后各留 5 秒余量；优先 `-c copy`，不行就 `libx264 -crf 14 -preset slow`，保持原分辨率和帧率），每段不超过 380MB。片段在原片中的起止时间写进 manifest。
- 一两个小时的直播回放不要整段保留，只截关键片段。
- 每个视频用 ffmpeg 生成一张 4×4 缩略图拼板，每张缩略图标上时间码，存到 `previews/<文件名>.jpg`；每张图片生成长边 1280 的预览，存到 `previews/<文件名>.jpg`。
- 用 ffprobe 填写分辨率、帧率、时长。

## manifest.csv

按 `manifest_template.csv` 的列，一个文件一行（同一编号的多个候选各占一行）。列说明：

- `asset_id`：编号，如 NA-09
- `candidate`：候选序号，01、02……
- `file_path`：相对 assets/ 的路径
- `shot_ids`：用在哪些镜头，照抄上表“用在”
- `description`：一句话描述画面内容
- `source_org`：发布机构
- `source_page_url`：素材详情页
- `direct_file_url`：实际下载的文件地址
- `original_id`：机构编号（nasa_id、PIA 编号、Flickr 照片 ID、馆藏号）
- `license`：许可（Public Domain / NASA media guidelines / CC BY-NC 2.0 / CC0 / Pixabay License / 未声明）
- `license_url`：许可说明页
- `credit_line`：片尾署名写法，如“NASA/JPL-Caltech”
- `media_type`：video / image / audio
- `width`、`height`、`fps`、`duration_s`、`filesize_mb`
- `excerpt_of`、`excerpt_in`、`excerpt_out`：如果是截取的片段，填原文件路径和原片中的起止时间（秒）
- `key_moments`：视频里关键画面的时间码，如“00:12 点火; 00:19 离塔”
- `notes`：其他说明（叠加层位置、网站版权声明原文、拿不准的地方）

## REPORT.md

收集完后写一份报告，包括：

1. 完成情况表：每个编号找到几个候选、最佳候选是哪个、一句话理由。
2. 没找到或只找到低质量版本的编号，以及原因。
3. **待用户确认**：需要从 YouTube/X 获取的 SpaceX 视频（链接 + 时间码），以及授权不明确的素材。
4. 总文件数与总大小。

- 每个编号要么有合格候选，要么在 REPORT.md 里说明原因。
- manifest.csv 每一行都填了来源页、许可、署名和技术参数。
